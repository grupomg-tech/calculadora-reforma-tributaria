# Contributing

Thanks for taking the time to contribute. Issues and pull requests are welcome in Portuguese or English. By participating you agree to the [Code of Conduct](CODE_OF_CONDUCT.md).

## Reporting bugs and ideas

Open an [issue](https://github.com/grupomg-tech/calculadora-reforma-tributaria/issues/new/choose) using the bug or feature template. For bugs, say what you did, what you expected and what happened; a screenshot and the browser console output help a lot. If the bug depends on your backend's response, paste a **redacted** sample of the JSON — never real company data.

Issues labelled [`good first issue`](https://github.com/grupomg-tech/calculadora-reforma-tributaria/labels/good%20first%20issue) are scoped for newcomers; [`help wanted`](https://github.com/grupomg-tech/calculadora-reforma-tributaria/labels/help%20wanted) marks work the maintainer would like help with.

## Development setup

```sh
git clone https://github.com/grupomg-tech/calculadora-reforma-tributaria.git
cd calculadora-reforma-tributaria
npm ci
npm run dev
```

You do not need a backend: open <http://localhost:8080/dashboards/dashboard-cliente/?demo=1> to work with the built-in fictional dataset, or set `VITE_DEMO=true` in `.env.local` (see `.env.example`). More in [docs/development.md](docs/development.md).

## Branches and commits

- Branch from `main`, one topic per branch: `<type>/<topic>` (e.g. `fix/pie-empty-labels`, `docs/api-contract`).
- Commit messages follow [Conventional Commits](https://www.conventionalcommits.org): `feat:`, `fix:`, `docs:`, `test:`, `build:`, `ci:`, `chore(deps):`, `refactor:`. Write the subject in English, imperative mood.
- Keep dependency major bumps separate from feature work.

## Before opening a pull request

```sh
npm run lint
npm run typecheck
npm run test:coverage
npm run build
```

The same checks run in CI on every pull request, plus `npm audit` and CodeQL. `main` only accepts changes through pull requests with green checks.

## Pull request review criteria

A PR is merged when:

1. CI, Security and CodeQL are green.
2. New behaviour has tests ([docs/testing.md](docs/testing.md)); changes to `src/lib` always do.
3. Changes to the API contract (`src/lib/api-types.ts`) update the fixture and the README section.
4. User-visible changes have an entry under `[Unreleased]` in `CHANGELOG.md`.
5. The PR template is filled in (what, how to test, checklist).

The maintainer reviews every PR; expect a first response within a week.

## Code style

- TypeScript `strict`; no `any`.
- Computation in `src/lib` as pure functions; components stay presentational.
- Do not edit `src/components/ui/` by hand (generated by shadcn/ui).
- UI strings live in `src/i18n/` (`pt-BR` default, `en` via `?lang=en`); code, comments and docs are English.

## Tax rules

The demo model in `src/lib/demo.ts` is intentionally simple and is not a source of truth for tax rules. Proposals that change tax behaviour must cite the legal basis (EC 132/2023, LC 214/2025 or later regulation) in the issue or PR, and get the `tax-rules` label.
